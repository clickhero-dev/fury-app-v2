Visão Geral

Projeto: fury-app-v2 — apps/api/src

Stack: Express + TypeScript + BullMQ + Drizzle ORM + Neon PostgreSQL + Redis

Arquivos Analisados: ~130 source files | Testes: 54 suites (31% coverage)

Auditoria executada em 15 fases, cobrindo arquitetura, dependências, camadas (controller/service/repository), SOLID, clean code, segurança, performance, testabilidade, modularização e dead code.

Forças da Arquitetura ✅

• Entry point limpo com bootstrap assíncrono e graceful shutdown
• Middleware pipeline consistente (rate-limit → auth → tenant → controller)
• Provider pattern bem implementado para abstração de APIs externas
• Cache em Redis em múltiplos níveis (campanhas, localizações, respostas HTTP)
• JWT + Refresh tokens com hash SHA-256 e comparação timing-safe
• Meta tokens criptografados com AES-256-GCM
• Rate limiting com sliding window atômico via Lua Redis

Fraquezas da Arquitetura ❌

• Controllers com acesso direto ao DB (quebra da arquitetura em camadas)
• Bug crítico no Authorization header do OpenRouter (usa `***` em vez de `Bearer`)
• N+1 queries no superadmin.listTenants
• Dependência circular entre serviços (campaigns → meta)
• CORS aberto para todas as origens
• Rotas sem proteção de autenticação/tenant/subscription consistentes
• Ausência de structured logging e correlation IDs
• Cobertura de testes baixa (31%) e 9 testes falhando

Top 10 Dívidas Técnicas

🔴 1. Bug: Authorization header do OpenRouter
openrouter.service.ts:21 — CRÍTICO — 5min
Template literal quebrado: `Authorization: *** ${apiKey}` em vez de `Authorization: Bearer ${apiKey}`. Impede autenticação no OpenRouter, gerando erro 502 em todas as chamadas de chat e geração de imagem.
🔴 2. Controller monolítico Superadmin
superadmin.controller.ts:1-778 — CRÍTICO — 2h
778 linhas com DB direto, bcrypt, schemas, regras de negócio. Viola SRP e Layered Architecture. Extrair para SuperadminService.
🟠 3. N+1 queries em listTenants
superadmin.controller.ts:130-155 — ALTA — 30min
Para listar N tenants, executa 1+N+N queries (tenants + usuários + subscriptions). Para 100 tenants = ~201 queries. Usar LEFT JOIN com GROUP BY.
🟠 4. CampaignsController não usa CampaignsService como classe
campaigns.controller.ts — ALTA — 30min
A classe CampaignsService existe com DI, mas o controller chama funções wrapper soltas exportadas do mesmo arquivo. Unificar para usar a classe com DI via constructor.
🟠 5. Rotas sem proteção consistente
routes/index.ts — ALTA — 1h
Várias rotas não usam AUTH_TENANT_SUB: /meta, /automation, /studio, /budget, /fury, /goals, /billing, /openrouter. Risco de acesso não autorizado.
🟠 6. Automation controller com DB direto
automation.controller.ts — ALTA — 30min
Controller acessa db diretamente em vez de delegar ao service. Extrair para AutomationRulesService.
🟠 7. Budget controller com persistência direta
budget.controller.ts:60-69 — ALTA — 15min
Controller insere diretamente no DB em vez de delegar ao BudgetOptimizerService. Viola separação de camadas.
🟡 8. CORS aberto para todas origens
index.ts:29 — MÉDIA — 5min
Callback de CORS aceita TODAS as origens. Configurar FRONTEND_URL como origem permitida.
🟡 9. Auth service sem DI
auth.service.ts — MÉDIA — 1h
Todas as funções usam db como dependência global. Converter para classe com DI de IAuthRepository para facilitar testes.
🟡 10. Campaigns controller com cache inline
campaigns.controller.ts:180-203 — MÉDIA — 30min
Controller gerencia cache diretamente (getCampaignsCache, setCampaignsCache). Mover para middleware de cache dedicado.

Patch Sugerido — Bug Crítico OpenRouter

🐛 Correção Imediata (prioridade máxima)

openrouter.service.ts — Linha 21
// ❌ ATUAL (quebrado)
headers: { 'Content-Type': 'application/json', Authorization: *** ${apiKey}` },

// ✅ CORRIGIDO
headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${apiKey}` },

Impacto: Sem esta correção, 100% das chamadas ao OpenRouter retornam 502. Chat e geração de imagem estão completamente quebrados.

📐 Extração de Schema — campaigns.controller.ts

Criar schemas/campaigns.schema.ts
// Extrair ~80 linhas de validação do controller para schema file
import { z } from 'zod';
export const createWizardSchema = z.object({
  objective: z.enum(['sales', 'leads', 'engagement', 'traffic', 'awareness']),
  ...
});

🔒 Fechar CORS

index.ts — Configuração CORS
// ❌ ATUAL (aceita tudo)
app.use(cors());

// ✅ CORRIGIDO
const FRONTEND_URL = process.env.FRONTEND_URL || 'http://localhost:3000';
app.use(cors({ origin: [FRONTEND_URL, 'https://app.fury.ai'] }));
